# 用户、资金与营销模块

初版实现日期：2026-11-18。2026-11-19 业务后端已迁移为 Go / MySQL 8，前端继续 Vue 3 / Element Plus，使用现有 Telegram iOS Icons 和白色界面规范。当前运行与机器人内购买流程见 [Bot 财务流程](bot-commerce.md)；文末 PHP 命令仅保留为初版记录。

## 使用入口

- `/user`：余额、搜索奖励、营销中心、充值订单、广告订单、历史账单。
- `/user/collections`：原有收藏与收录申请。
- 机器人私聊 `/account`、`/wallet` 或菜单「我的」：余额、机器人内充值、广告购买及账单。`/login` 单独获取可选的网站登录码，5 分钟失效、只能使用一次，数据库只存哈希。
- `/admin/commerce-settings`：支付、奖励及网站根地址。
- `/admin/recharges`、`/admin/wallets`、`/admin/wallet-entries`：充值核账、用户余额及不可编辑的账单。
- `/admin/ad-slots`、`/admin/ad-orders`：广告位配置、订单审核及投放异常处理。
- 既有管理员和普通用户仍分别使用独立表、Cookie 和 CSRF。财务及营销模块接入操作权限和字段权限，新权限默认仅超级管理员拥有。

Telegram 自动账户与独立注册的网站账户不合并。通过机器人登录的用户进入原 Telegram 账户和钱包，不会冒领同名网站账户。

## 金额与账务

所有余额采用 USDT 的六位小数。数据库使用 BIGINT 最小单位；API 金额使用字符串；拒绝浮点输入、科学计数法、负数和七位以上小数。不得直接编辑余额。

充值、奖励、扣款、退款在事务中锁用户及钱包，写余额时同时插入流水。`business_key` 唯一，充值交易哈希唯一，充值/广告创建请求编号与用户组成唯一键。拒绝、失败或越权操作回滚全部资金改动。有资金或订单历史的用户不可删除，可停用。

## USDT-TRC20

使用 Tronscan 官方 API：

```text
GET https://apilist.tronscanapi.com/api/token_trc20/transfers
GET https://apilist.tronscanapi.com/api/transaction-info?hash=...
Header: TRON-PRO-API-KEY
Mainnet USDT: TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t
```

2026-11-18 已通过实际只读请求观察接口字段，使用已配置密钥成功查询收款地址；未执行真实转账。官方文档网站当时被 Cloudflare 阻挡，接口字段依据官方 API 实际响应核实。

用户先创建订单，输入整数充值金额 1–100000。系统随机分配 0.000001–0.999999 的小数尾款，完整应付金额全部入账。收款地址和应付金额组合不重复使用，订单保留当时的地址快照，修改收款配置不会改变已有订单。

付款时限 30 分钟。同一用户最多三笔未过期待处理订单，创建和手工核查均限流。后台任务自动查询匹配转账，也允许用户填写交易哈希加快核查；哈希并不决定交易归属。

入账条件必须全部满足：

1. 指定交易哈希匹配；成功状态 `contractRet=SUCCESS`。
2. `confirmed=true`、`revert=false`、至少 19 个确认。
3. 主网 USDT 合约、TRC20 类型、六位小数。
4. 接收地址及原始整数金额精确匹配订单。
5. 区块时间在订单创建和付款截止时间之间。
6. 只有一条匹配转账，交易哈希尚未入账。

最近 24 小时过期的订单继续核对，以接住在有效时段内发出但延迟确认的付款；更旧订单仍可手工提交哈希核查。过期后付款、金额不符、分笔付款、其他币种不自动入账，需要人工联系处理，不能将其假装已完成。

自动查询采用有界分页；地址交易非常密集时可提交准确哈希。首版面向低流量，共享地址加唯一金额。后续如改为专属充值地址，应接入具备地址归属与密钥管理能力的钱包服务。

API Key 使用 AES-256-GCM 保存，独立密钥文件 `.commerce.key`（0600、被 Git 忽略）；页面只显示配置状态，不返回明文。备份数据库时需同时安全备份该文件。只查询，不保存钱包私钥，也不提供自动对外转账功能。

线下转账填写后台收款说明后启用。用户提交付款人、时间和转账编号，管理员核实真实到账后批准；系统不会将用户文字凭证视为已付款。

## 搜索奖励

默认关闭。按北京时间每天首次有效关键词搜索奖励一次，必须有自然搜索结果。私聊、群聊和通过机器人登录的网站账户共享同一用户限制；独立注册的网站账户仍是独立身份。

管理员配置单次奖励、全站每日上限、单用户累计上限。翻页、空关键词、无结果和开放 API 不发奖励；唯一 `(user_id, day)` 配合事务锁防止同日重复发放。此规则不是跨账号反女巫识别，推广前应结合现有验证码和搜索限流控制预算。

## 六类广告位

初始六个广告位均关闭，默认参考价 10 USDT / 7 天，需管理员设定价格并开放。关闭广告位只停止新购，已有订单按快照履约。

| 类型 | 首版投放行为 |
| --- | --- |
| 关键词排名 | 精确匹配词，在自然结果前展示一条带广告标签的链接 |
| 品牌展示 | 按品牌词展示链接，不宣称 Telegram 官方认证 |
| 搜索顶部轮播 | 每次新搜索从可投放广告中选择一条；同一个 Bot 搜索会话保持稳定 |
| 搜索底部按钮 | Bot 分页下方展示带广告标签的链接按钮；网站结果底部显示对应推广链接 |
| 群组置顶 | 独占广告位、容量 1，发送并置顶成功才开始计时；到期只取消本订单消息的置顶 |
| 频道广告 | 发布一条广告，实际发送成功后计时；到期不重复发布，也不自动删帖 |

购买在事务内检查广告位、剩余容量和余额，按服务端价格扣款并创建待审核订单。每个关键词分别计算关键词/品牌位容量。报价或时长变化需用户重新确认。

待审核不展示；拒绝全额退回余额。站内搜索广告通过审核即开始；群组和频道广告先核实机器人身份及目标权限，再交给后台任务投放。所有广告明确标注「广告」，不减少自然结果的 12 条默认分页。

Telegram 发送不支持业务幂等键。任务发送前保存 `sending` 状态，超时或进程中断不盲目重发，进入「投放待核实」。后台可核实真实消息 ID 后恢复计时，或者退款。发送成功但置顶失败时保留消息 ID。投放中止、未发出或有争议的广告可由具备权限的管理员执行全额退款，资金业务键防止重复退款。

## 启动与验证

```sh
php think app:upgrade-commerce
php think commerce:work
php think commerce:work --once
php scripts/dev.php
```

开发 supervisor 同时启动 Web、Bot 长轮询和财务 worker；worker 每轮结束后约 30 秒运行下一轮，MySQL advisory lock 防止多实例重复投放。日志在 `runtime/commerce.log`，不打印凭据或完整请求 URL。生产环境需由进程管理器守护这些命令。

```sh
php tests/commerce.php
php tests/commerce_concurrency.php
php tests/commerce_http.php
```

测试使用回滚事务和明确的临时账户，不执行真实链上支付，不向真实群/频道发送广告。临时 UI 账户使用 `php scripts/commerce-ui-fixture.php` 创建，验收后运行同脚本加 `cleanup` 删除账户及未付款测试订单；若账户已有资金流水，清理脚本拒绝删除。
