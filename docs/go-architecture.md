# StarIndex Go 架构与运行说明

## 架构选择

后端采用 Go 模块化单体，MySQL 8.0 保存业务数据，Vue 3 + TypeScript + Element Plus 负责网站、用户中心和后台。浏览器界面继续使用 Vue；Go 承担 HTTP API、身份认证、权限判断、搜索、机器人和财务任务，不需要把浏览器代码改写为 Go。

当前本机工具链为 Go 1.27.4；`server/go.mod` 声明最低 Go 1.26.0。这些是项目当前的安装及编译基线，不代表对所有后续版本的兼容性承诺。

```text
浏览器（Vue）── HTTPS / JSON ── Go HTTP 服务 ─┐
开放搜索 API ── Bearer Token ── Go HTTP 服务 ─┤
Telegram ── getUpdates 长轮询 ── Go Bot worker ├─ MySQL 8.0
TRONSCAN ── 查询交易证明 ── Go 财务 worker ───┘
```

| 边界 | 职责与入口 |
| --- | --- |
| 网站 | `/`，公开资源检索、类型和分类筛选、资源详情 |
| 用户中心 | `/user`，账号、Telegram 绑定、收藏、收录、钱包、充值、广告 |
| 后台 | `/admin`，资源、用户、角色、财务、广告、群策略、Bot 配置 |
| 开放接口 | `/api/v1/search`，独立密钥、每日额度、分钟限流 |
| Telegram worker | 私聊及群聊搜索、专属交互、验证、收录、登录授权 |
| 财务 worker | 链上订单核验、广告发布及到期处理、账务事务 |

业务代码位于 `server/internal/app`，命令入口位于 `server/cmd/starindex`。先保持同仓库、同领域服务、同数据库，避免早期运维承担分布式事务和服务发现成本。后续可独立部署 HTTP、Bot、财务进程，仍使用同一可执行文件。

## 数据与兼容

沿用 `ts_*` 业务表和原有用户 ID、资源、订单、钱包及配置。新增 Telegram 授权挑战、用户 Telegram 资料和 Go worker 状态表。迁移以补充表和列为主，不清空已有数据、不重置已有管理员、不改写余额。

MySQL 使用 InnoDB、`utf8mb4`、参数化 SQL、事务和唯一键；连接池默认最多 25 个连接、10 个空闲连接。时间统一按 `Asia/Shanghai` 处理。链接先规范化后计算哈希，资源与收录申请共同校验重复；并发写入由事务、链接锁和唯一约束兜底。

设计目标是 MySQL 8.0 及向后续 MySQL 版本迁移。升级数据库前需在副本上执行迁移、并发账务测试和搜索回归；SQL 模式、排序规则及执行计划的变化仍需验证。这里不宣称已经测试所有更新版本。

`.env` 保存本地数据库连接。Bot Token 和支付 API Key 使用原项目兼容的 AES-GCM 配置；迁移机器时同时保留 `.bot-token.key`、`.commerce.key`，它们不进入前端和公共接口。原 PHP 文件保留作迁移对照及回退资料，Go 业务运行不调用 PHP。

## 管理员与权限

管理员使用 `ts_admins`、`ts_admin_sessions`，普通用户使用 `ts_users`、`ts_sessions`。两类身份的登录入口、Cookie 和会话表独立；拥有普通用户登录态不能访问后台。

RBAC 包含管理员—角色、角色—操作权限、角色—字段权限。一个管理员可分配多个角色，启用角色的授权取并集，未授权默认拒绝。每次后台请求重新计算权限，角色停用或撤权在后续请求生效。

授权同时作用于三个层次：

1. 前端路由、菜单和按钮按权限展示。
2. 后端接口独立检查读取、创建、修改、删除、审核等操作权限。
3. 字段采用「隐藏 / 只读 / 可编辑」；响应投影移除不可读字段，写入白名单拒绝不可写字段，资源筛选和排序也检查对应字段权限。

`access.manage` 为超级管理员专属能力，普通角色不能自行授予；超级管理员不能被删除或停用，当前登录管理员不能删除自己。管理员密码重置会撤销其现有会话。权限配置修改写入审计记录。

字段权限用于控制数据和业务操作，不能代替未来多商户系统的数据隔离；若增加租户，需要把租户边界加入每条相关查询。

## Telegram 绑定与登录

网页发起 5 分钟一次性授权挑战，浏览器和 Bot 使用两枚不同的随机凭据，数据库只保存凭据哈希。浏览器轮询凭据通过 `X-Telegram-Challenge-Token` 请求头传递，避免出现在 URL 查询参数。前端仅保存在组件内存中。

用户打开专属 Bot 链接后，在私聊中点击确认。服务端检查 Telegram 用户、聊天身份、Bot 身份和请求有效期。浏览器消费已确认挑战后创建网站会话；事务锁和消费状态防止重复使用。取消、过期或无法恢复的失败停止轮询，重新发起后使用新凭据。

绑定已有网站账号还要求原网站用户、原会话与 CSRF。一个 Telegram 身份只能绑定一个网站账号；已有独立账号不会自动合并余额、订单或历史记录。解绑必须验证网站密码，保留网站账号并撤销其他会话。首次设置网站密码需在 Telegram 登录后的 15 分钟内完成，后续修改需原密码。

Telegram 自动账号使用 `tg_` 保留前缀。解绑后再次以同一 Telegram 登录时，如果旧用户名仍被占用，生成新的随机后缀账号，不会隐式重新绑定旧账户。一次性网站登录码改由 `/login` 主动获取；`/account` 和 `/wallet` 进入机器人内钱包。

## 保留的业务能力

- 网站搜索、资源/分类/收录 CRUD、收藏、审核、重复链接与禁投校验。
- `/start` 欢迎语标签、可配置按钮行、Telegram iOS 图标、紧凑标题及后台分页条数。
- 私聊、群聊、话题群搜索；翻页与筛选绑定发起用户，其他人点击返回提示；引用消息失效后降级为普通回复。
- `/add 链接` 自动获取标题；群管理命令、广告规则及六种搜索验证方式。
- 独立用户钱包、线下充值审批、USDT-TRC20 交易核验、每日首次有效搜索奖励。
- 广告位、购买、审核、投放、到期和退款；金额使用整数最小单位，余额和流水在同一事务提交，业务唯一键防止重复记账。
- 后台 Bot Token 配置、搜索验证、API 密钥、系统设置和审计日志。

财务与群安全的规则和测试边界详见 `docs/go-commerce-security.md`。链上和 Telegram 传输层可在测试中替换，自动化测试不等于真实资金到账或真实群投放验收。

## 构建与运行

以下命令从项目根目录执行，已有 `.env` 时直接复用：

```sh
# 安装当前项目使用的 Go 工具链（本机已安装可跳过）
sh scripts/install-go.sh

# 前端依赖只需安装一次；后续修改重新构建
cd frontend
pnpm install --frozen-lockfile
cd ..
sh scripts/build.sh

# 编译 Go 服务
cd server
../runtime/tools/go/bin/go build -trimpath -o ../runtime/starindex ./cmd/starindex
cd ..

# 增量迁移，然后启动网站、Bot 与财务 worker
runtime/starindex migrate --root .
runtime/starindex all --root . --addr 127.0.0.1:8088
```

也可使用 `sh scripts/go-dev.sh` 编译并启动。命令 `serve` 仅启动 HTTP，`bot` 仅启动 Telegram，`commerce` 仅启动财务任务。`import --file 路径 --source 来源` 默认预检，增加 `--apply` 才写入；`maintain` 清理过期临时状态。`GET /healthz` 检查 Go 服务及数据库连接。

部署时上传可执行文件、`public/build`、`public/icons`、`resources/icons/telegram-ios`、数据库迁移目录及安全配置。用进程管理器运行服务，Nginx/Caddy 代理 HTTPS 请求到本机 HTTP 端口。运行目录需要允许 worker 写锁文件；不公开项目根目录和密钥文件。反向代理场景需单独验证真实客户端 IP 与 HTTPS Cookie 设置，不能无条件信任客户端自带转发头。

Bot 长轮询当前按单 worker 运行，同目录文件锁防止本机重复启动；跨主机部署仍须由部署配置确保同一个 Bot 只运行一个长轮询实例。财务 worker 使用 MySQL 专用连接锁防止重复执行。启动 Go Bot 前停止旧 PHP Bot，避免同一 Token 的轮询竞争。

## 当前边界与扩展路线

Go 迁移提升运行和部署的一致性，不会自动带来千万数据或几十万同时翻页的容量。当前搜索仍是 MySQL `LIKE`、总量查询及 `LIMIT/OFFSET`，公共检索限制到前 100 页；深分页、中文相关性排序、共享结果缓存和分布式 Bot 任务尚未实现。

先通过真实数据测量慢查询、接口延迟、连接池等待和 Telegram 限流。需要扩大时，再把搜索读取迁往专用搜索引擎，以 MySQL 为事实来源，通过可靠事件同步索引；使用 Redis 保存短期搜索结果和游标，把 Bot 接入与发送拆成有界队列，并按聊天限速。数据库分页应改为游标或搜索快照，避免大量用户重复计算相同结果。

第三方发送与本地事务无法原子提交，极端故障窗口仍可能出现重复消息；不能承诺严格一次投递。按钮验证也只能降低误触及简单刷屏，不能作为强身份或强人机识别证明。
