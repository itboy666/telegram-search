# Go 财务与机器人安全迁移验收

现有 MySQL 业务表、用户 ID、订单、钱包和加密配置继续使用。运行路径已改为 Go 原生实现，业务处理不调用 PHP 子进程。原 PHP 文件仅供迁移对照和回退使用。

## 财务与广告

| 能力 | Go 实现与兼容性 |
| --- | --- |
| 钱包、流水 | 余额和流水在同一事务写入；锁定用户及钱包；业务键唯一；整数存储 USDT 六位小数 |
| 线下充值 | 提交凭证、独立管理员审核、批准入账、拒绝保留记录；重复审批不会再次入账 |
| USDT-TRC20 | 保留现有地址和 API Key；自动分配不复用的精确付款金额；交易哈希唯一 |
| 链上核验 | 核对主网 USDT 合约、收款地址、原始金额、时间窗口、SUCCESS、confirmed、revert、至少 19 次确认；字段缺失时拒绝入账 |
| 密钥 | 兼容现有 `.commerce.key` 和 PHP AES-256-GCM 信封；管理接口不返回密钥明文或密文 |
| 搜索奖励 | 首次有效首页搜索；每人每天唯一；全站日上限、单用户累计上限；默认设置沿用原数据库 |
| 广告购买 | 六类广告、后端报价、容量控制、先扣余额、审核后生效、拒绝或退款仅退款一次 |
| 群与频道投放 | 审核前确认机器人权限；发送成功后计时；不确定的发送转为人工核对，不自动重复发帖 |
| 到期处理 | 广告到期下线；只取消本订单记录的置顶消息，频道历史广告不删除 |
| 管理权限 | 原财务模块权限、字段读取与写入白名单、用户与管理员身份隔离、写操作 CSRF |
| 接口 | 保留 `/user/api/commerce/*` 和 `/admin/api/commerce/*` 的前端请求与响应形状 |

财务 worker 使用专用 MySQL 连接持有 `starindex_commerce_worker` 锁；不同进程不能同时执行该轮任务。业务事务和唯一键仍独立防止重复入账。每轮自动检查待支付订单及最近 24 小时内过期的链上订单；只有付款时段内发出的交易可入账。

## 验证码与群管理

已迁移 emoji 选择、顺序点击、按钮确认、图片字母数字、四则运算、随机组合六种验证形式。PNG 图片直接由 Go 生成，不再依赖 PHP GD。

挑战绑定机器人、Telegram 用户、聊天、消息和话题。答案只保存哈希；验证码到期、策略变化、错误次数、冷却期和每分钟限流均由数据库校验。并发正确回答只能恢复搜索一次。重复发送关键词不会在有效挑战期间继续刷出新验证码。遗留挑战的上下文仍兼容读取。

群命令保留 `/groupsettings`、`/captcha`、`/ads`、`/adwords`、`/allowdomain`、`/flood`。群主或当前管理员通过 Telegram 实时身份查询后才能修改；开启删除类规则需机器人具备删消息权限。匿名管理员须切换为个人身份配置。总后台禁用群覆盖时，群内不能修改验证模式。

广告检测识别文本与图片说明中的 URL、Telegram 隐藏链接实体、UTF-16 URL 偏移、关键词及常见零宽字符。域名白名单按完整主机名或其子域判断。群主与管理员免拦截；无法确认发言者身份时不会删除消息，也不会把疑似广告再次回显成搜索结果。

## Telegram 登录与绑定

浏览器持有独立的挑战凭证，机器人私聊内由 Telegram 用户确认授权；两者同时验证成功后才创建登录会话。轮询凭证只通过请求头传递，不进入 URL。挑战限定用途、到期时间、原始网站用户和原始会话，消费后不可重放。

绑定时不会合并已有账户或迁移其钱包。该 Telegram 身份已属于其他用户时直接拒绝绑定。登录、绑定、验证码登录、密码修改和解绑在事务提交后才返回成功；绑定、改密码和解绑在锁定用户后重新检查会话是否仍有效，避免已退出的会话完成敏感操作。

用户设置密码后才能解绑 Telegram；修改密码和解绑会撤销其他会话。解绑后保留原网站账户及其业务数据。后续单独通过同一个 Telegram 身份登录将创建新的账户，不会通过相同用户名重新绑定原账户。原 PHP bcrypt 密码继续可用。

## 验证

在项目的 `server` 目录运行：

```sh
go test ./internal/app
STARINDEX_DB_TEST=1 STARINDEX_AUTH_TEST=1 go test -race ./internal/app \
  -run 'TestAuth|TestCommerce|TestSecurity|TestMoney|TestTRON|TestTRC20|TestAdValidation'
```

数据库测试创建独立随机名称及 ID 的临时夹具并清理，包括：

- 8 路并发消费 100 USDT，每笔 20 USDT，仅 5 笔成功，余额和流水一致。
- 8 路并发审核同一充值，只记账一次。
- 8 路并发购买广告，仅生成余额允许的 5 个订单，没有孤立扣款或未扣款订单。
- 过期订单的有效时段交易仍可确认；重复核账只入账一次。
- 用户归属、CSRF、普通用户不能使用后台接口。
- 旧 PHP 支付配置及加密密钥可由 Go 读取。
- 验证码所有者、话题、消息、重放、顺序、冷却、到期与策略失效。
- 管理员消息免删、查询身份失败时保守处理、普通成员违规链接删除。
- Telegram 完整登录与绑定、原始会话隔离、已占用身份、禁用账户、过期及取消授权。
- 8 路并发 Telegram 首次登录只产生一个账户，6 路消费同一挑战仅成功一次。
- 登录会话撤销、跨站来源及 CSRF 校验、`/login` 一次性验证码、防止重复使用。
- PHP bcrypt 兼容、密码设置后撤销其他会话、解绑后保留网站密码登录。

验证使用模拟的链上交易证明与 Telegram transport，没有真实转账、发帖、置顶或删除外部消息。生产支付和群/频道投放仍需使用真实运营账户做最终验收。按钮确认仅用于降低误触和简单刷屏，不能作为强人机识别证明。
