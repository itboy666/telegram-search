# Go 群管理实现与验收

群管理开关默认关闭。每群配置存储在 `ts_bot_groups`，后台沿用 `bot_groups.read/update` 及字段读写白名单。配置权限与搜索验证码独立。

## 内容拦截

`message_max_chars` 为 0 时关闭，开启后允许 1–4096 个 Unicode 码点，检查消息正文及媒体说明。超长优先于媒体、转发、广告和防刷规则。图片、视频、文件、音频、语音、贴纸、动画、视频便笺、联系人、位置、投票等可整体禁止；转发支持新旧 Telegram 消息字段。

机器人通过实时 `getChatMember` 保留群主和管理员豁免。无法确认身份时不删除，也不把疑似违规内容回显为搜索结果。删除失败同样停止搜索，后台 `last_error` 记录实际字数、阈值及权限错误。设置删除规则前核验机器人删除权限。

群命令包括 `/maxlength 200`、`/joinverify emoji`、`/welcome on`、`/media on`、`/forwards on`，沿用 `/ads`、`/flood`、`/adwords`、`/allowdomain` 和实时管理员身份校验。`off` 关闭对应开关，`/maxlength 0` 关闭字符限制。

## 欢迎与新人验证

欢迎模板支持 `{{tag}}`，标签白名单：

`user_id`、`nickname`、`username`、`first_name`、`last_name`、`mention`、`chat_id`、`chat_title`、`chat_username`、`datetime`、`date`、`time`、`timezone`、`bot_username`。

空模板默认“欢迎 {{mention}} 加入 {{chat_title}}！”。模板最多 2000 个 Unicode 码点，未知或残缺标签被拒绝。文字与用户资料转义后发送，只有系统生成的 mention 是 HTML。展开后的欢迎正文以完整片段截到最多 3000 个 UTF-16 单位，保留 mention 标签，并给验证说明留出空间。

欢迎开启时入群即发送。新人验证开启时，即使关闭普通欢迎，也发送必要的验证入口。验证完成后在私聊反馈，不重复群欢迎、不自动发起搜索。

新人验证支持按钮、emoji、顺序 emoji、图片字母数字、四则运算和随机组合。只在超级群组中开启，并要求机器人拥有限制成员权限。新人先被持续禁言，再通过群内深链接进入机器人私聊；所有验证码均在私聊处理，所以不会出现“已禁言却要求在群内输入答案”的冲突。

挑战绑定机器人、群、成员、入群代次和最新私聊题目。数据库只保存答案哈希。每人最多尝试次数、到期时间、顺序题进度、离群/重入和重复更新由数据库校验。`chat_member` 与 `new_chat_members` 的同次通知会去重；批量服务消息逐成员处理。较新的明确入群事件可恢复遗漏的离群通知。若离群事件遗漏且两次入群发生在同一秒，系统保守视为同一代，不重新禁言或重发欢迎。

默认失败动作是保持持续禁言，不设置自动解除时间。可配置移出群，移出时临时封禁 60 秒，之后允许重新加入。失败、通知不确定或权限不足均记入持久状态与群错误字段，需管理员处理。

普通和编辑消息先经过内容拦截，再检查新人搜索资格。资格检查只读数据库，没有每条消息查询 Telegram 的开销。未通过、验证失败、人工核对和离群状态不能用旧搜索按钮或旧搜索验证码继续发群搜索结果。没有挑战记录的存量成员正常搜索；已通过、管理员豁免、仅欢迎成员正常搜索。收到其他管理员明确恢复发言的成员事件后，记录 `admin_released` 并恢复搜索。管理员关闭本群新人验证也会放开搜索资格，但不会擅自解除 Telegram 上已经存在的禁言，后者仍由管理员处理。

## 权限恢复边界

成功验证后读取当前群默认权限恢复，不能把所有权限无条件设为 true。恢复需要同时满足：

- 本次限制由机器人执行，并收到对应的机器人 `chat_member` 确认事件。
- 实时成员权限仍与本次持续禁言完全一致。
- 没有观测到其他管理员随后修改成员权限。
- 机器人仍有相应管理权限，成员仍在群内。

已有管理员禁言、缺失成员事件、权限不一致、操作结果不确定等均转入 `manual_review`，不会自动解除。Telegram 权限接口不提供原子条件更新；最终查询与权限请求之间仍有很窄的并发窗口。因此不能宣称在管理员同时修改权限时具有绝对原子保证。对同时管理的敏感群，管理员应查看人工接管提示，并避免在验证放行瞬间重复调整同一成员。

## 调度与故障处理

`GroupManagementOnce(ctx)` 由机器人进程的单个调度器调用。挑战按机器人、状态、到期时间及操作租约建立索引；一次最多领取 50 个到期记录，采用事务行锁和 `SKIP LOCKED`。事务提交后才调用 Telegram，没有每成员定时器或 goroutine。

权限操作和欢迎发送在调用前保存状态。重启后过期的操作租约会转人工核对，避免在不确定的 HTTP 结果之后重复禁言、解禁或发送欢迎。批处理遇到 Telegram 延迟时完成时间会增加；当前实现适合起步阶段，未宣称经过十万群规模压测。大规模部署需要进一步拆分任务队列、按群限速、监控积压与 Telegram 限流。

## 集成与测试

主消息流程使用以下接口：

- `GroupMemberEvent(ctx, event, botID)`：`chat_member` 事件。
- `GroupServiceMessage(ctx, message, botID)`：仅处理新成员/离群服务消息。
- `GroupSearchAllowed(botID, chatID, userID)`：内容拦截之后的新人搜索资格，以及搜索入口、旧搜索按钮和旧搜索验证码恢复前的统一检查。
- `JoinVerificationStart(ctx, message, botID, challengeID)`：`/start join_...` 私聊入口。
- `JoinVerificationCallback(ctx, callback, botID)`：`j:` 回调。
- `JoinVerificationText(ctx, message, botID)`：私聊回复文字验证码。
- `GroupManagementOnce(ctx)`：批量到期扫描。

入群/服务事件附带 `_update_id`，用来隔离旧事件。机器人轮询显式订阅 `chat_member`。这些事件需要机器人管理员身份；不能只依赖普通群消息订阅。
